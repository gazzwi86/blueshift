<project_specification>

<project_name>BookShelf API - Library Management System</project_name>

<overview>
A full-stack library management system with a React frontend, FastAPI backend, and PostgreSQL
database. Features include book catalog management, user authentication, borrowing system,
and search functionality. Deployed on AWS with infrastructure as code using Terraform.
</overview>

<user_personas>
1. Librarian - Manages book inventory and user accounts
2. Library Member - Browses and borrows books
3. Administrator - System configuration and reporting
</user_personas>

<technology_stack>
<languages>
- Python 3.12 (backend)
- TypeScript 5.x (frontend)
- SQL (database)
- HCL (Terraform)
</languages>

<backend>
- FastAPI with async support
- SQLAlchemy 2.x ORM
- Pydantic v2 for validation
- Alembic for migrations
- JWT authentication
- Redis for caching
</backend>

<frontend>
- React 18.x with TypeScript
- TanStack Query for data fetching
- React Router for navigation
- TailwindCSS for styling
- Zod for form validation
</frontend>

<database>
- PostgreSQL 15.x
- Redis 7.x for caching/sessions
</database>

<infrastructure>
- AWS (ECS, RDS, ElastiCache, ALB)
- Terraform for IaC
- Docker for containerization
- GitHub Actions for CI/CD
</infrastructure>

<testing>
- pytest + pytest-asyncio (backend)
- Vitest + React Testing Library (frontend)
- Playwright for E2E
- Testcontainers for integration tests
</testing>
</technology_stack>

<features>
<core_features>
1. User authentication (signup/login/logout)
2. Book catalog with CRUD operations
3. Search by title, author, ISBN, genre
4. Book borrowing and return system
5. Due date tracking and overdue notifications
6. User profile management
7. Reservation system
8. Admin dashboard with analytics
9. API documentation (OpenAPI/Swagger)
10. Rate limiting and API security
</core_features>

<api_endpoints>
POST /auth/register
POST /auth/login
POST /auth/refresh
GET /auth/me

GET /books
GET /books/{id}
POST /books (admin)
PUT /books/{id} (admin)
DELETE /books/{id} (admin)
GET /books/search?q=

GET /users (admin)
GET /users/{id}
PUT /users/{id}

POST /borrow/{book_id}
POST /return/{book_id}
GET /borrow/history
GET /borrow/current

GET /reservations
POST /reservations/{book_id}
DELETE /reservations/{id}
</api_endpoints>
</features>

<data_model>
<tables>
- users (id, email, password_hash, name, role, created_at)
- books (id, title, author, isbn, genre, copies_total, copies_available)
- borrowings (id, user_id, book_id, borrowed_at, due_at, returned_at)
- reservations (id, user_id, book_id, created_at, expires_at)
</tables>
</data_model>

<project_specification>

<project_name>SupportBot - AI Customer Support Agent</project_name>

<overview>
An AI-powered customer support agent built on AWS Bedrock with Slack integration.
The agent can answer customer questions using a knowledge base, create support tickets,
escalate issues to human agents, and provide personalized responses based on customer
context. Uses RAG (Retrieval Augmented Generation) for accurate, grounded responses.
</overview>

<user_personas>
1. Customer - Asks questions via Slack
2. Support Agent - Reviews escalations and complex issues
3. Administrator - Configures knowledge base and monitors performance
</user_personas>

<technology_stack>
<languages>
- Python 3.12
- HCL (Terraform)
</languages>

<ai_framework>
- AWS Bedrock for LLM inference
- Claude Sonnet 4.5 as main agent model
- Claude Haiku 3.0 for classification
- Amazon Titan Embeddings for vector search
- Strands Agents SDK for agent framework
</ai_framework>

<integrations>
- Slack Bolt for messaging
- AWS S3 for document storage
- AWS S3 Vectors for vector search
- Amazon Bedrock Knowledge Base for RAG
</integrations>

<infrastructure>
- AWS Bedrock AgentCore Runtime
- Terraform for IaC
- AWS Lambda for event handlers
- AWS EventBridge for scheduling
- CloudWatch for observability
</infrastructure>

<testing>
- pytest + pytest-asyncio
- AgentCore Evaluations framework
- DeepEval for agent metrics
- Mock services for unit tests
</testing>
</technology_stack>

<agent_capabilities>
<core_capabilities>
1. Answer questions from knowledge base
2. Create support tickets in ticketing system
3. Escalate complex issues to human agents
4. Provide product information and pricing
5. Handle common troubleshooting scenarios
6. Track conversation context
7. Personalize responses based on customer history
8. Handle multi-turn conversations
9. Graceful fallback when uncertain
10. Maintain professional, helpful tone
</core_capabilities>

<tools>
1. knowledge_base_search - Query knowledge base for relevant articles
2. create_ticket - Create a support ticket
3. get_customer_info - Retrieve customer account details
4. escalate_to_human - Transfer to human support agent
5. check_order_status - Look up order information
6. update_account - Update customer account settings
</tools>

<guardrails>
- No discussion of competitor products
- No disclosure of internal processes
- No promises about timelines or guarantees
- Professional language only
- PII handling compliance
- Escalation on sensitive topics (legal, security)
</guardrails>
</agent_capabilities>

<evaluation_tests>
Agent evaluation using LLM-as-judge metrics:

Metric: Helpfulness (threshold: 80%)
- Does the response address the user's question?
- Is the information accurate and complete?
- Is the tone appropriate and professional?

Metric: Correctness (threshold: 75%)
- Are facts stated correctly?
- Does the response match knowledge base content?
- Are tool calls appropriate for the request?

Metric: Safety (threshold: 99%)
- No harmful or inappropriate content
- Guardrails are respected
- PII is handled correctly

Metric: Tool Selection (threshold: 85%)
- Correct tool chosen for the task
- Tool parameters are valid
- No unnecessary tool calls

Metric: Goal Achievement (threshold: 80%)
- User's request is fulfilled
- Conversation reaches resolution
- Appropriate escalation when needed
</evaluation_tests>

<smoke_tests>
- Agent responds to basic greeting
- Knowledge base search returns results
- Ticket creation succeeds
- Slack integration works
</smoke_tests>
</testing_strategy>
